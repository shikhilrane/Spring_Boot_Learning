REDIS :
    1. Redis is a caching provider.
       (Redis ek caching provider hai)
    2. Redis is a key-value type of storage.
       (Redis ek key-value type storage hai)
    3. We can use Redis for caching, the pub-sub model (publisher and subscriber) like Kafka, and also as a database, but using it as a database can be costly.
       (Redis ko caching, pub-sub model (publisher-subscriber) jaise Kafka, aur database ke roop me bhi use kar sakte hain, lekin database ke roop me use karna costly ho sakta hai)
    4. Redis is widely used for caching, and we will also use Redis only for caching purposes. We will maintain a separate database and use Redis to cache that data.
       (Redis ka sabse zyada use caching ke liye hota hai, aur hum bhi Redis ko sirf caching ke liye use karenge. Hum alag database rakhenge aur us data ko cache karne ke liye Redis use karenge)
    5. Why should we not use in-memory caching for production-ready applications?
       In-Memory Caching:
           Suppose we have deployed our application on an EC2 instance and are using in-memory caching.
           (Maan lo humne apni application EC2 par deploy ki hai aur in-memory caching use kar rahe hain)
           As long as the application is running, the cache is available. But when the application stops or restarts, the in-memory cache is completely cleared.
           (Jab tak application chal rahi hoti hai tab tak cache available hota hai, lekin application stop ya restart hote hi in-memory cache puri tarah erase ho jata hai)
           For example, if cache data for 100 users is stored in memory and we deploy a new feature, the application restarts and all cached data for those users is lost.
           (Agar memory me 100 users ka cached data stored hai aur hum new feature deploy karte hain, to application restart hone par un sab users ka cached data delete ho jata hai)
       Redis Caching:
           When we use Redis caching with our EC2 application, the cache is stored separately from the application because Redis runs as a separate server/service.
           (Jab hum EC2 application ke saath Redis caching use karte hain, to cache application ke andar nahi balki alag Redis server/service me store hota hai)
           Therefore, even if the application restarts, the cached data in Redis is not affected.
           (Isliye agar application restart bhi ho jaye, tab bhi Redis ka cached data affect nahi hota)
           Also, a single Redis server can be shared by multiple EC2 instances behind a load balancer.
           (Ek hi Redis server ko multiple EC2 instances ke saath load balancer ke through use kiya ja sakta hai)
    6. Installing and Using Redis :
        Install the redis from homebrew using "brew install redis" command
        Run redis server/service using "brew services start redis" command
        Once the redis is running, you can test it by running "redis-cli"
        set the name using "set name your_name"
        set the name using "set password your_password"
        Understanding Redis with following flow :
            1. REDIS FLOW :
                1. Install Redis
                       ↓
                2. Start Redis Server
                       ↓
                3. Open Redis CLI
                       ↓
                4. Store data in Redis
                       ↓
                5. Retrieve data from Redis
                       ↓
                6. Use Redis with Spring Boot for caching
                       ↓
                7. Stop Redis Server
            2. STEP BY STEP :
                1. INSTALL REDIS (Only one time)
                    Mac : brew install redis
                2. START REDIS SERVER
                    brew services start redis
                    OR
                    redis-server
                3. CHECK REDIS SERVER IS RUNNING
                    redis-cli ping
                    Output:
                    PONG
                4. OPEN REDIS CLI
                    redis-cli
                    Now terminal changes to : 127.0.0.1:6379>
                    Matlab:
                    Ab tu Redis ke andar hai
                5. STORE DATA IN REDIS
                    SET name "Shikhil"
                    Output:
                    OK
                6. GET DATA FROM REDIS
                    GET name
                    Output:
                    "Shikhil"
                7. UPDATE DATA
                    SET name "Rane"
                    GET name
                    Output:
                    "Rane"
                8. DELETE DATA
                    DEL name
                    Output:
                    (integer) 1
                9. SEE ALL KEYS :
                    KEYS *
                10. CLEAR ALL REDIS DATA :
                    FLUSHALL
                11. EXIT REDIS CLI
                    exit
                    OR
                    quit
                12. STOP REDIS SERVER
                    brew services stop redis
                    OR

            3. SPRING BOOT FLOW :
                Client Request
                      ↓
                Spring Boot
                      ↓
                Check Redis Cache
                      ↓
                --------------------------
                | Cache Hit              |
                | Data found in Redis    |
                | Return data directly   |
                --------------------------
                OR
                --------------------------
                | Cache Miss             |
                | Data not found         |
                | Fetch from DB          |
                | Store in Redis         |
                | Return response        |
                --------------------------
            4. IMPORTANT :
                Redis = Separate server
                Spring Boot default cache:
                    → In-memory RAM
                    → Lost after restart
                Redis cache:
                    → Separate process/server
                    → Survives app restart
                    → Shared among multiple apps
    7. Configure Redis in Spring-boot Application :
        1. Add dependency in pom.xml :
            <dependency>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-starter-data-redis</artifactId>
            </dependency>
        2. Configuration :
            spring.cache.type=redis                             # Tells Spring Boot to use Redis as the caching provider.
            spring.data.redis.host=your-redis-host              # Specifies the hostname/IP address of the Redis server.
            spring.data.redis.port=your-redis-port              # Specifies the port number on which the Redis server is running.
            spring.data.redis.password=your-redis-password      # Specifies the password used to connect to the Redis server.
            spring.data.redis.ssl.enabled=false                 # Enables or disables SSL connection for Redis communication.
        3. We also need to implement Serializable in the DTO class so that objects can be stored in Redis cache.
           (Hume DTO class me Serializable implement karna padta hai taaki objects Redis cache me store ho sake)
        4. In Redis CLI, if we run the command "KEYS *", it shows all cached employees with names in the format: CACHE_NAME::ID (CACHE_NAME is variable that we created in service)
           (Redis CLI me agar hum "KEYS *" command chalate hain, to cache me stored employees CACHE_NAME::ID format me dikhte hain)
        5. When we check the CacheManager interface, we can see that it is also implemented by RedisCacheManager.
           (Jab hum CacheManager interface check karte hain, tab hume dikhta hai ki RedisCacheManager bhi usko implement karta hai)
        6. As of now, we are using a localhost Redis server, but in production-grade applications, we should not use a localhost server.
           (Abhi hum localhost Redis server use kar rahe hain, lekin production-grade applications me localhost server use nahi karna chahiye)
           To overcome this:
               1. We can create a separate server to store Redis cache.
                  (Hum Redis cache store karne ke liye alag server bana sakte hain)
               2. We can use third-party providers that offer managed cache servers. These providers may use Redis or other caching technologies such as Hazelcast, EhCache, or Caffeine.
                  (Hum third-party providers use kar sakte hain jo managed cache servers provide karte hain. Ye Redis ya Hazelcast, EhCache, Caffeine jaise caching technologies use kar sakte hain)
           We will use Redis Cloud as the third-party provider.
           (Hum Redis Cloud ko third-party provider ke roop me use karenge)

        9. We can configure more cache settings here:
           We know that this application is using the RedisCacheManager class, so we can configure it inside the CachingConfig class by returning a CacheManager bean from there.
               (Hume pata hai ki ye application RedisCacheManager class use kar rahi hai, isliye hum usko CachingConfig class me CacheManager bean return karke configure kar sakte hain)
           This bean creates a RedisCacheManager for managing cache operations using Redis.
               (Ye bean Redis ka use karke cache operations manage karne ke liye RedisCacheManager create karta hai)
           It also adds a custom prefix ("my-redis-") before cache names stored in Redis.
               (Ye Redis me store hone wale cache names ke pehle custom prefix "my-redis-" add karta hai)
        10. Time duration of data in Redis DB:
            1. In the Redis Insight application, we can see "No Limit", which indicates that the cache entry will never be removed automatically.
                   (Redis Insight application me "No Limit" dikhata hai, iska matlab cache entry automatically remove nahi hogi)
               If the data is not updated or removed manually, it will remain in the Redis database permanently.
                   (Agar data manually update ya remove nahi kiya gaya, to wo Redis DB me permanently rahega)
               Therefore, we need an eviction mechanism for cache data.
                   (Isliye hume cache data ke liye eviction mechanism ki zarurat hoti hai)
            2. To achieve this, we need to provide a TTL (Time To Live) in the configuration.
                   (Iske liye hume configuration me TTL (Time To Live) dena padta hai)
               After prefixCacheNameWith(), add:
               .entryTtl(Duration.ofSeconds(60))
               This means the cache data will remain in Redis for 60 seconds only.
                   (Iska matlab cache data Redis me sirf 60 seconds tak rahega)
            3. So now, the data will exist in Redis for only 60 seconds.
                   (Ab data Redis me sirf 60 seconds tak hi rahega)
        11. Time duration with Time-To-Idle:
            1. If someone is continuously using the cached data, then we may not want to remove that data from the Redis database.
                (Agar koi continuously cached data use kar raha hai, to hum shayad us data ko Redis DB se remove nahi karna chahenge)
            1. After adding : .enableTimeToIdle();
               along with : .entryTtl(Duration.ofSeconds(60))
               the cache duration gets reset to 60 seconds whenever the API is accessed.
                (Jab hum .enableTimeToIdle() use karte hain, tab API hit hone par cache ka duration firse 60 seconds reset ho jata hai)
            2. For example, if we fetch data for id = 2 and after 20 seconds we make the same request again, then the TTL will again become 60 seconds.
               (Example ke liye, agar hum id = 2 ka data fetch karte hain aur 20 seconds baad same request firse karte hain, to TTL firse 60 seconds ho jayega)
        12. Configure key and value serialization for Redis cache :
            1. By default, Redis stores data in binary format, which is not easily readable.
                (Default me Redis data ko binary format me store karta hai, jo easily readable nahi hota)
            2. Therefore, we configure serializers for both cache keys and values.
                (Isliye hum cache keys aur values ke liye serializers configure karte hain)
            3. .serializeKeysWith(RedisSerializationContext.SerializationPair.fromSerializer(new StringRedisSerializer())) is used to store cache keys in a readable String format.
                (Ye cache keys ko readable String format me store karne ke liye use hota hai)
            4. .serializeValuesWith(RedisSerializationContext.SerializationPair.fromSerializer(new GenericJackson2JsonRedisSerializer())) is used to store cache values in JSON format.
                (Ye cache values ko JSON format me store karne ke liye use hota hai)
            5. This makes the data easy to read and inspect in Redis Insight or Redis CLI.
                (Isse data Redis Insight ya Redis CLI me easily readable ho jata hai)
            6. It is considered a good practice to configure serialization explicitly in production applications.
                (Production applications me serialization explicitly configure karna ek achhi practice mani jati hai)
            7. We can see that the data is now stored in a readable format in Redis Insight.
                (Hum Redis Insight me dekh sakte hain ki ab data readable format me store ho raha hai)
