Cross Cutting Concerns
    1. Cross-cutting concerns are aspects of a program that affect multiple modules and often cannot be modularized by traditional object-oriented (OO) design. This is where Aspect-Oriented Programming (AOP) steps in, providing a powerful tool to modularize cross-cutting concerns and weave them into your main business logic, without entangling the core code.
       (Cross-cutting concerns wo cheezein hoti hain jo application ke multiple modules ko affect karti hain aur traditional OOP se easily separate nahi hoti. AOP in concerns ko modularize karke main business logic me integrate karne me help karta hai bina core code ko messy banaye.)
    2. In the realm of Spring, a prominent Java framework, AOP provides a seamless solution for managing these concerns.
       (Spring framework me AOP cross-cutting concerns jaise logging, security, transactions ko easily manage karne ka solution deta hai.)

Aspect Oriented Programming :
    1. The world of software development has long embraced Object-Oriented Programming (OOP) as a standard paradigm to promote code reusability. However, when it comes to cross-cutting concerns, OOP alone often falls short. Enter Aspect-Oriented Programming (AOP) — a paradigm that complements OOP to handle concerns that span multiple parts of an application.
       (Software development me OOP ko code reusability ke liye use kiya jata hai. Lekin jab cross-cutting concerns jaise logging, security, transactions ki baat aati hai to sirf OOP kaafi nahi hota. Yaha AOP use hota hai jo OOP ko complement karta hai aur application ke multiple parts me spread concerns ko handle karta hai.)
    2. At its core, AOP is about separating concerns in a software application. It offers a way to modularize cross-cutting concerns independently of the main business logic.
       (AOP ka main idea concerns ko separate karna hai. Ye cross-cutting concerns ko main business logic se alag modularize karne ka tarika deta hai.)
    3. AOP Principle:
        1. Controller, Service, and Repository classes should contain only pure business logic.
        2. Secondary logic such as logging, transaction management, security, and other cross-cutting concerns should not be written inside these classes. Instead, they should be handled separately using AOP so that the core business code remains clean, modular, and easy to maintain.
        (Controller, Service aur Repository classes me sirf business logic hona chahiye. Secondary logic jaise logging, transaction management, security wagairah in classes ke andar nahi likhna chahiye. Inhe AOP ke through alag handle kiya jata hai taaki main business code clean aur maintainable rahe.)
    4. There is already AOP dependency present in pom.xml in 'spring-boot-starter-data-jpa'
        (spring-boot-starter-data-jpa dependency ke andar already AOP related libraries present hoti hain, isliye basic AOP features use karne ke liye alag se dependency add karne ki zarurat nahi padti.)

Benefits of AOP :
    1. Cleaner and more focused code
    2. Reduced code Duplication
    3. Enhanced Modularity
    4. Loose coupling and enhanced flexibility

Key concepts in AOP
    • Aspect: an aspect is a module that encapsulates a single cross-cutting concern.
        (Aspect ek module hota hai jo ek specific cross-cutting concern ko handle karta hai jaise logging, security ya transaction management.)
    • Join Point: These are specific points in your program where you might want to inject additional behavior or logic.
        (Join Point program ke wo specific points hote hain jaha hum additional logic add kar sakte hain, jaise method call, method execution, etc.)
    • Advice: It's the code associated with an aspect that gets executed when a specific join point is reached.
        (Advice wo code hota hai jo aspect me likha hota hai aur jab specified join point hit hota hai tab execute hota hai.)
    • Pointcut: They are expressions that match certain join points.
        (Pointcut ek expression hota hai jo define karta hai ki kaunse join points par advice apply hoga.)
    • Weaving: This is the process by which aspects are integrated into the main business logic. It can happen at different times: compile-time, load-time, or even runtime.
        (Weaving wo process hai jisme aspects ko main business logic ke sath integrate kiya jata hai. Ye compile time, load time ya runtime par ho sakta hai.)
