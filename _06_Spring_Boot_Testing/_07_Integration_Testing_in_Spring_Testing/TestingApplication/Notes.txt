Integration Testing :
    01. Testing a whole application in one flow
        (Isme hum poori application ko ek flow me test karte hain jaise Controller → Service → Repository → Database.)
    02. We haven't tested controller layer because unit testing of controller layer doesn't make any sense as it doesn't have any logical part to execute
        (Controller me usually koi heavy business logic nahi hota, isliye uski unit testing ka zyada benefit nahi hota.)
    03. But we will test controller, service and repository together in Integration Testing
        (Integration testing me hum controller, service aur repository ko ek saath test karte hain.)
    04. Many issues, such as configuration errors, missing data, or incorrect business logic, only surface when components interact with each other
        (Bahut se errors tabhi pata chalte hain jab different components ek saath kaam karte hain.)
    05. Integration testing serve as a safeguard when changes are made to the codebase
        (Jab code me changes kiye jaate hain tab integration tests ensure karte hain ki application break na ho.)
    06. They help ensure that new changes do not break the existing functionality, making regression testing more effective
        (Ye check karte hain ki naye changes se purani functionality affect na ho.)
    07. In Integration testing, we want an api call and we are testing on data from that api call
        (Isme hum real API call karte hain aur uske response aur data ko test karte hain.)
    08. To do that we use library called WebTestClient which provides a fluent API and support making real HTTP requests to your application
        (WebTestClient ka use karke hum GET, POST, PUT, DELETE jaise HTTP requests bhejte hain.)
    09. Although, WebTestClient is primarily associated with WebFlux Applications, it can be also used with Spring MVC applications when set up correctly
        (Normally WebFlux me use hota hai, lekin proper configuration ke saath Spring MVC me bhi use ho sakta hai.)
    10. Use the @AutoConfigureWebTestClient to autoconfigure the WebTestClient
        (Ye annotation automatically WebTestClient ko configure karta hai taaki hum API calls test kar sakein.)
            <dependency>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-starter-webflux</artifactId>
                <scope>test</scope>
            </dependency>
    11. We are not going to mock anything in Integration testing
        (Integration testing me mocks use nahi karte, sab real components use hote hain)

Steps :
    1. Add required dependencies in pom.xml for testing and Testcontainers
       (WebTestClient aur Testcontainers use karne ke liye required dependencies add karte hain.)
    2. Create Test for Controller only, as we already have tests for service and repository layer
       (Service aur repository ki unit testing already ho chuki hai, isliye integration testing me controller ko test karenge.)
    3. Press "cmd+shift+T" on controller that we want to test and use IT after the name of test to denote that this is for Integration Testing
       (Example: EmployeeControllerTestIT jaha IT ka matlab Integration Test hota hai.)
    4. Create an AbstractIntegrationTest class
       (Is class me integration testing ke liye common configuration rakhenge.)
       This class contains common configuration required for integration testing such as:
       - WebTestClient configuration
       - Loading full Spring Boot application context
       - Starting PostgreSQL Testcontainer
       - Common test objects like testEmployee and testEmployeeDto
    5. In AbstractIntegrationTest :
       - Autowire WebTestClient so it can be used to call API endpoints
         (Isse hum API endpoints ko test karne ke liye HTTP requests bhej sakte hain.)
       - Create sample test data (testEmployee and testEmployeeDto) which will be reused in tests
         (Ye common test data hai jo har integration test me reuse hoga.)
    6. Extend EmployeeControllerTestIT from AbstractIntegrationTest
       (Isse controller test class ko WebTestClient, configuration aur test data automatically mil jayega.)
    7. Autowire EmployeeRepository inside EmployeeControllerTestIT
       (Iska use database me test data save ya delete karne ke liye karte hain before API call.)
    8. Now write integration tests in EmployeeControllerTestIT to test the full flow:
       Controller → Service → Repository → Database
       (Yaha hum real API call karte hain aur verify karte hain ki poora application flow sahi kaam kar raha hai.)
