       (Isliye Mockito ko alag se dependency add karne ki zarurat nahi hoti.)
    2. As we are learning unit testing as of now, we should independently test service layer, but to test service, we want support of related repository as well and we should not use actual repository for that in unit testing

    3. For that, we will use Mockito library to mock repository layer
       (Mockito repository ka fake object create karta hai jo real database call nahi karta.)
    4. This class is all about Mockito and Mocking we will see service layer in separate class
    5. Mockito -
        1. Mockito is useful for testing components in isolation without relying on their actual implementation or external dependencies. Like everywhere employeeRepository is used, we want to mock there
           ((Mockito ka use karke hum kisi component ko independently test kar sakte hain bina uske real dependencies use kiye. Jaise service layer me employeeRepository ko real database se connect karne ki jagah mock kar dete hain.))
        2. Mockito can be used for :
            Mocking : Creating mock objects to simulate the behaviour of real objects.
                      (Mocking ka matlab real object ka fake version banana jo testing ke liye use hota hai.)
            Stubbing : Defining the behaviour of mock objects when specific methods are called.
                       (Stubbing me hum define karte hain ki mock object ka method call hone par kya return karega.)
            Verification : Checking if certain methods were called on mock objects.
                           (Verification se check karte hain ki koi particular method mock object par call hua hai ya nahi.)
    3. Mockito Methods -
        1. Creating Mock :
            with @Mock Annotation
                (Isme @Mock annotation use karke kisi dependency ka mock object create karte hain.)
                Example:
                    @Mock
                    private EmployeeRepository employeeRepository;
            with Mockito.mock(Classname)
                (Isme Mockito.mock() method use karke manually mock object create kiya jata hai.)
                Example : EmployeeRepository employeeRepository = Mockito.mock(EmployeeRepository.class);
        2. Stubbing Mock :
            when (T methodCall) : Specifies a method call to be stubbed
                                  (Is method se define karte hain ki mock object ka kaunsa method call hone wala hai.)
            thenReturn(T value) : Sets a return value for a stubbed method call
                                  (Ye define karta hai ki jab wo method call ho to kya value return honi chahiye.)
                                  Example : Mockito.when(employeeRepository.findById(1L)).thenReturn(Optional.of(employee));
            thenThrow(Throwable... throwables) : Throws an exception when a stubbed method call is made
                                                 (Isse hum define kar sakte hain ki method call hone par exception throw ho.)
                                                 Example : Mockito.when(employeeRepository.findById(1L)).thenThrow(new RuntimeException("Employee not found"));
        3. Verifying Methods :
                verify(T mock) : Verifies that a method was called on a mock
                                 (Ye check karta hai ki mock object ka koi particular method call hua hai ya nahi.)
                                 Example : verify(employeeRepository).findById(1L);
                verify(T mock, VerificationMode mode) : Verifies that a method was called with a specific verification mode
                                                        (Isme hum define karte hain ki method kitni baar call hua hai ya kaise call hua hai.)
                                                        Example : verify(employeeRepository, times(1)).findById(1L);
                                                    VerificationMode modes:
                                                        1. times(int wantedNumberOfInvocations) : Verifies the exact number of invocations.
                                                                                                  (Check karta hai ki method exact kitni baar call hua hai.)
                                                                                                  Example : verify(employeeRepository, times(1)).findById(1L);

                                                        2. never() : Verifies that a method was never called.
                                                                     (Verify karta hai ki method ek baar bhi call nahi hua.)
                                                                     Example : verify(employeeRepository, never()).deleteById(1L);
                                                        3. atLeastOnce() : Verifies that a method was called at least once.
                                                                           (Verify karta hai ki method kam se kam ek baar call hua hai.)
                                                                           Example : verify(employeeRepository, atLeastOnce()).findById(1L);
                                                        4. atLeast(int minNumberOfInvocations) : at least called x times
                                                                                                 (Verify karta hai ki method kam se kam x baar call hua hai.)
                                                                                                 Example : verify(employeeRepository, atLeast(2)).findById(1L);
                                                        5. atMost(int maxNumberOfInvocations) : at most called x times
                                                                                                (Verify karta hai ki method maximum x baar tak hi call hua hai.)
                                                                                                Example : verify(employeeRepository, atMost(3)).findById(1L);
                                                        6. only() : Verifies that no other method was called on the mock.
                                                                    (Verify karta hai ki mock object par sirf wahi method call hua hai aur koi aur method call nahi hua.)
                                                                    Example : verify(employeeRepository, only()).findById(1L);
        4. Argument Captor:
            It allows you to capture arguments for further assertions or validation, making it useful when you want to inspect arguments that were passed to a method call.
            ArgumentCaptor : Used to capture the arguments passed to a mocked method so that we can verify or assert them later.
                             (ArgumentCaptor ka use karke hum dekh sakte hain ki mock method ko kaun-sa object ya value pass hui thi.)
            ArgumentCaptor.forClass(ClassName.class) : Creates an ArgumentCaptor for a specific class type.
                                                       (Ye method kisi particular class ke object ko capture karne ke liye ArgumentCaptor banata hai.)
                                                       Example : ArgumentCaptor<Employee> employeeCaptor = ArgumentCaptor.forClass(Employee.class);
            capture() : Captures the argument passed to the mocked method.
                        (Ye method mock method ko pass hui value ko capture karta hai.)
                        Example : verify(employeeRepository).save(employeeCaptor.capture());
            getValue() : Returns the captured argument so that we can perform assertions on it.
                         (Ye captured argument ko return karta hai jisse hum us par assertions kar sakte hain.)
                         Example : Employee capturedEmployee = employeeCaptor.getValue();
                                   assertThat(capturedEmployee.getEmail()).isEqualTo("test@gmail.com");

    4. Create an instance of EmployeeServiceImpl and inject mocked dependencies using @InjectMocks.
    5. Create a mock object of EmployeeRepository using @Mock.
    6. Create a test method for the service method.
    7. Setup mock objects according to Employee entity.
        7.1 @BeforeEach runs before every test case.
        7.2 Create mock Employee object using builder pattern.
        7.3 Convert Employee entity to EmployeeDto using ModelMapper.
        7.4 Declare mock Employee object.
        7.5 Declare mock EmployeeDto object.
        7.6 Create mock ModelMapper so real mapping logic is not executed.
    8. Follow AAA pattern (Arrange, Act, Assert)
        8.1 Arrange – Prepare test input and stub repository behaviour.
        8.2 Act – Call the service method being tested.
        8.3 Assert – Verify that the returned result is correct.
    9. Test creating a new employee and capture saved entity using ArgumentCaptor.
        9.1 Arrange – Stub repository behaviour for create operation.
            (findByEmail() ko stub karte hain taaki empty list return ho aur save() ko stub karte hain taaki mockEmployee return ho jab new employee save ho.)
        9.2 Act – Call the service method createNewEmployee().
            (Service method ko call karte hain jo internally email check karta hai aur phir repository.save() ko call karta hai.)
        9.3 Assert – Verify the returned EmployeeDto and captured saved entity.
            (Returned DTO null nahi hai aur email match karta hai ya nahi check karte hain. ArgumentCaptor ka use karke verify karte hain ki repository.save() ko kaunsa Employee object pass hua tha.)
